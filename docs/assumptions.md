# Assumptions

Reversible defaults chosen so work can continue. Each one is recorded with its owner, the date and what it affects. The product owner can change any of them.

| #   | Assumption                                                                                                                                                                                                                                      | Owner                     | Date       | Impact if changed                                                               |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ---------- | ------------------------------------------------------------------------------- |
| A1  | **Light is the default theme.** Dark mode is opt-in and remembered in `localStorage`. The OS colour-scheme setting is not followed automatically.                                                                                               | Product owner (confirmed) | 2026-11-27 | Following the OS setting would be a small change in `apps/web/src/lib/theme.ts` |
| A2  | English is the first interface and course language; the code is ready for localisation but no translations exist.                                                                                                                               | Requirements §18          | 2026-11-27 | Adding languages needs i18n routing and translated content                      |
| A3  | Public course browsing is allowed; lessons require enrolment.                                                                                                                                                                                   | Requirements §18          | 2026-11-27 | Access rules in the Enrollment module                                           |
| A4  | Free access for the MVP; billing is a later epic.                                                                                                                                                                                               | Requirements §18          | 2026-11-27 | Billing would add subscriptions and payments tables and a provider ADR          |
| A5  | Cloud vendor and region are not chosen. Code stays portable (plain Node processes, Postgres, Redis, S3-compatible storage).                                                                                                                     | Product owner (open)      | 2026-11-27 | Decide before the hardening phase                                               |
| A6  | AI provider is not chosen. A mock provider is used until the mentor phase.                                                                                                                                                                      | Product owner (open)      | 2026-11-27 | Decide at the start of the AI mentor phase                                      |
| A7  | Emails are stored normalised (trimmed, lower-case). A database CHECK constraint enforces it, making the unique index case-insensitive. The Identity module must normalise before writing.                                                       | Engineering               | 2026-11-27 | Switching to `citext` would need a migration                                    |
| A8  | Primary keys use PostgreSQL's `gen_random_uuid()` (UUIDv4).                                                                                                                                                                                     | Engineering               | 2026-11-27 | Time-ordered UUIDv7 could be adopted later for index locality                   |
| A9  | Integration tests use a separate database whose name must contain `test`; the test setup refuses to reset anything else.                                                                                                                        | Engineering               | 2026-11-27 | None                                                                            |
| A10 | The web app loads a small inline script to apply the saved theme before first paint. When a Content Security Policy is added, it must allow this script via a nonce or hash. CSP was not added in Phase 2; it moves to the hardening phase.     | Engineering               | 2026-11-27 | CSP work in the hardening phase                                                 |
| A11 | Colours follow the Figma variables, with two contrast fixes: placeholder text is `#64748B` (Figma `#94A3B8` is 2.56:1) and `success-subtle` is `#EDF8F1` (Figma `#E6F6EC` gives 4.48:1 with success text). See `docs/design-system/tokens.md`.  | Engineering               | 2026-11-27 | Revert if the designer prefers another fix                                      |
| A12 | The repository is private on GitHub and CI runs on GitHub Actions.                                                                                                                                                                              | Product owner (confirmed) | 2026-11-27 | None                                                                            |
| A13 | Sign-in is email and password only. The "Continue with Google" button in the design is left out until social sign-in is specified (provider, account linking).                                                                                  | Engineering               | 2026-11-27 | Adding OAuth needs an `auth_identities` table and a provider ADR                |
| A14 | Rate limits fail open when Redis is unavailable, so sign-in keeps working during a Redis outage. Failures are logged.                                                                                                                           | Engineering               | 2026-11-27 | Failing closed would lock everyone out during Redis incidents                   |
| A15 | Input borders use the Figma `border-default` `#CBD5E1` (1.48:1 against white, below the 3:1 WCAG target for component boundaries). Fields are still identified by visible labels. Raised with design rather than changed.                       | Design (open)             | 2026-11-27 | A darker border token, e.g. `#8C9AAE`                                           |
| A16 | Session lists show browser and operating system only. Location ("Dhaka, Bangladesh") in the design is not shown, because we don't store IPs in plain text or use a GeoIP database.                                                              | Engineering               | 2026-11-27 | GeoIP lookup would need a provider and a privacy review                         |
| A17 | Account deletion (`DELETE /users/me`) and the Settings danger zone are deferred: the requirements call for identity confirmation and a retention policy first. Avatar upload is deferred to the media storage work; the profile shows initials. | Product owner (open)      | 2026-11-27 | Needs a deletion policy (grace period, what is kept)                            |
| A18 | Multi-factor authentication for admins is deferred to before production launch.                                                                                                                                                                 | Engineering               | 2026-11-27 | Pre-production task                                                             |
| A19 | The common-password check is a short placeholder list shared by the API and the web app. It must be replaced by a breached-password check before launch.                                                                                        | Engineering               | 2026-11-27 | Pre-production task                                                             |
| A20 | Terms, privacy and AI disclosure pages are clearly marked drafts. `TERMS_VERSION` (`2026-11-draft`) is stored with each acceptance, so users can be asked to accept the final text later.                                                       | Product owner (open)      | 2026-11-27 | Legal review                                                                    |
| A21 | Skipping onboarding marks it complete, so learners aren't asked again. Goals and levels can be set later in Settings.                                                                                                                           | Engineering               | 2026-11-27 | Could nudge from the dashboard instead                                          |
| A22 | Preferred language offers English variants only (UK, US, AU, CA, IN, IE, NZ, ZA) until the interface is translated (see A2).                                                                                                                    | Engineering               | 2026-11-27 | Add languages with i18n                                                         |
